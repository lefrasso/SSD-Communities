SSD Communities · FY27 Design Language

Modern, elegant, unmistakably SSD.

Design principles

Four ideas that guide every screen

Translated from the FY27 brand's "locked design system" mindset into product UX. These principles resolve trade-offs when the guidelines don't spell out an answer.

◆

Clarity first

Generous whitespace, strong hierarchy, one primary action per view. The content is the hero — never the chrome.

◑

Calm & confident

Deep, saturated brand tones on light surfaces. Restraint over decoration; motion that reassures, never distracts.

▤

Visuals over tables

KPI tiles, cards, timelines and charts carry meaning. Tables are reserved for genuine data grids.

◈

Consistent system

Every screen is assembled from the same tokens and components, so the portal feels like one SSD FY27 family.

Color

A deep, disciplined palette

Brand tones are deep and high-contrast, so they read beautifully as text, icons and accents on light surfaces. Surfaces stay light gray or white — never cream, beige, or Office defaults.

Typography

Segoe Sans Display, with intent

Headings use Segoe Sans Display Semibold; body uses Segoe Sans Display Regular. Never Aptos, Segoe UI, Calibri, or Arial. Set the family explicitly wherever text is rendered.

Using the tokens

Wire it into the portal

The same values in this guide ship as ready-to-import token files, so the portal never hard-codes a hex or a font.

tokens.css

CSS custom properties on :root. Framework-agnostic — import once, use var(--color-blue) anywhere.

tokens.scss

SCSS variables & maps for SPFx .module.scss files, e.g. $color-blue.

theme.ts

Typed tokens + a Fluent UI theme for React web parts. import { ssdTheme }.
